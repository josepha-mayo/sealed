## Security changes

- Match receipts must form the exact ledger multiset; repeating a real winning
  receipt cannot increase its weight. The saved receipt-cloning exhibit checks
  this across TypeScript, Python and browser replay.
- Python now binds receipt timestamps when the card declares them. Before this
  repair, the backdated-receipt exhibit was accepted by Python.
- Trail verification derives result fields from the emitted schema and decoded
  accounts. Optional extra fields remain binding. Two valid saved trail cards
  previously failed because the verifier expected fields the emitter omits.
- Bank and claim surfaces require exact ledger membership. Bounty winner
  fields and board aggregates bind to decoded accounts. Venue seeds follow the
  venue kind. Missing snapshots fail closed.
- Browser deep links refuse absolute paths and traversal and report fetch
  failures. Reloading the ledger invalidates the last verdict. Verdict sealing
  refuses during an audit and after text edits. A public demo-key signature is
  labeled as an integrity witness, not proof of judge identity.
- The complete browser port now rejects receipt clones, duplicate bank run/
  receipt entries, backdated receipts, and dressed bounty winner timestamps.
  These five missing bindings were identified by replaying all saved exhibits.
- Empty receipt sets no longer turn a canned attack into an unchanged valid
  card: the attack creates a phantom receipt and verifies its rejection.
- Rust caps Merkle proofs at the supported depth and emits cancellation
  events. The market account-layout regression verifies benchmark offsets.

## SBF queue-validator repair

The fresh SBF build reported stack-overwrite diagnostics in GenPartPrivate and
ScoreChunk. Queue contexts now require the shared Arcium signer PDA to be
initialized explicitly, removing allocation from six large account validators.
`chain init` already performs this permissionless, idempotent bootstrap. The
E2E setup now does so too. Custom clients must call `init_signer_pda` before
their first queued computation. Account ownership, discriminator and seed
checks remain in typed-account validation. No account layout or program ID
changed. The historical capture does not validate this new source behavior.
